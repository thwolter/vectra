    Parsing & Normalisation

    VecAPI currently ships with an asynchronous LlamaParse integration that converts uploads into structured LangChain Document objects and Markdown suitable for downstream use. Parsing happens inside the worker when the UploadPipeline reaches the parse_document step.

    LlamaParser (src/vector/parser.py)

    • Wraps the official llama-parse client and exposes an async API (parse + to_markdown).
    • Accepts an optional loader factory which is useful for testing or swapping out the backend.
    • Enforces the presence of LLAMA_CLOUD__API_KEY; missing keys raise a ValueError before contacting the API.
    • Normalises metadata on every chunk:
    • parser: LlamaParser
    • node_index: incremental chunk index
    • Additional metadata from the original loader (page numbers, headings, etc.)
    • Applies heading-aware chunking via chunk_documents_by_headings, controlled through Settings.text_splitter (min/max heading levels).
    • Caches parsed docs so to_markdown() concatenates them without reprocessing.
    from vector.parser import LlamaParser

parser = LlamaParser()
docs = await parser.parse(file="/tmp/2024-q1-report.pdf")
markdown = await parser.to_markdown()

    Extending the Parser Layer

    While LlamaParse is the default, the architecture leaves room for alternative providers:

    1. Implement a loader factory/function that returns an object with an async aload() method yielding LangChain Document instances.
    2. Instantiate LlamaParser(loader=my_loader) and wire it into the pipeline via dependency overrides or a custom service factory.
    3. Ensure each document exposes necessary metadata (digest, source, etc.) — UploadPipeline adds fallbacks but custom parsers should preserve them.

    Future iterations may reintroduce a parser registry (Docling, ChatDoc, etc.). The current code structure mirrors that design; swapping implementations only requires updating UploadPipeline.parse_document.

    Markdown Normalisation

    • Markdown is generated by joining parsed chunk content with double newlines.
    • Heading chunker (src/vector/chunker.py) ensures Markdown blocks start with the associated heading so retrieval prompts include human-readable section titles.
    • Markdown storage is optional: when the parser cannot produce text (e.g., image-only PDFs), the pipeline logs a warning and skips the store_markdown step.

    Error Handling

    • Parser errors propagate up the pipeline; the worker marks the job failed with step='parse'.
    • Common failure scenarios:
    • llama-parse import errors → install the optional dependency (pip install llama-parse or add it to pyproject extras).
    • API rate limits → adjust concurrency (DRAMATIQ_THREADS) or upgrade plan.
    • Missing API keys → ensure LLAMA_CLOUD__API_KEY is set in the worker environment.

    Use OpenTelemetry traces (process_upload_message) and worker logs to debug parsing issues quickly.
